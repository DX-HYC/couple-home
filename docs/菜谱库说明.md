# 菜谱库说明

## 来源

内置菜谱来自开源项目 **[HowToCook](https://github.com/Anduin2017/HowToCook)**。

- 许可：**The Unlicense**（公共领域释放，可自由使用、修改、商用，无署名义务）
- 规模：373 道菜谱文件，解析成功 364 道 + 原有手写菜谱补充 52 道 = **416 道**
- 特点：每道菜都带**准确用量**（如「可乐 500ml」「白糖 10 克」）和**分步做法**，
  比原来 90 道手写菜谱细致得多

菜谱页底部也标注了来源，尊重开源社区。

## 文件

| 文件 | 说明 |
|---|---|
| `utils/recipes.js` | 生成产物，416 道菜。**不要手改**，会被重新生成覆盖 |
| `scripts/build-recipes-from-howtocook.py` | 生成脚本 |
| `tests/recipes.test.js` | 数据完整性校验（字段齐全、id/菜名唯一、分类合法、分页逻辑配套） |

## 重新生成

```bash
# 1. 克隆开源库
git clone --depth 1 https://github.com/Anduin2017/HowToCook.git

# 2. 生成
python scripts/build-recipes-from-howtocook.py <HowToCook路径> utils/recipes.js
```

脚本支持两种源目录：

1. **完整仓库**（下面有 `dishes/` 目录树）
2. **扁平目录** `raw/NNN.md` + `index.json`（序号→源路径映射），用于先批量抓取再离线生成

生成后务必跑一次 `node tests/recipes.test.js`。

## 源文件格式与解析映射

HowToCook 的菜谱是 Markdown：

```markdown
# 宫保鸡丁的做法
<描述段落，含「约需 40 分钟」>
预估烹饪难度：★★★
预估卡路里：960 大卡

## 计算
按照 1 盘的份量：
* 鸡翅 10 ～ 12 只
* 可乐 500ml

## 操作
1. 步骤一
   * 补充说明（缩进的子项）
2. 步骤二

## 附加内容
* 小贴士
```

映射关系：

| 源文件 | 生成字段 |
|---|---|
| `# XXX的做法` | `name`（去掉「的做法」） |
| `## 计算` 的列表项 | `ingredients`（带用量） |
| `## 计算` 的段落说明 | `tips`（换算/比例说明，很有用） |
| `## 操作` 的编号项 | `steps`（缩进子项以括号并入所属步骤） |
| `## 附加内容` | `tips` |
| `预估烹饪难度` | `duration` 的兜底依据 |
| 描述里的「耗时 N 分钟」 | `duration`（优先） |
| `按照 N 盘的份量` | `servings` |
| 菜名关键词 | `emoji` / `taste` / `category`（脚本里的规则表） |

## 几个刻意的处理

- **长食材说明拆走**：源站有些条目把用量和注意事项写一行
  （`老抽 7.5 ml（如果使用无糖可乐，追加 5 ml）`），
  列表摘要和详情格子里放不下。脚本把括号说明拆出来挪进 `tips`，
  主词保留在 `ingredients`。
- **碎步骤合并**：源站有些菜谱把「取肉沫」「加入调料」拆成独立三条，
  手机上读起来很碎。脚本会合并连续的功能性短句，
  但带火候/时间/温度等关键信息的步骤不动。
- **纯参考链接丢弃**（维基/小红书/YouTube）对做菜没帮助。
- **长度上限**：食材 ≤ 31 字、小贴士 ≤ 241 字，避免详情页变成一堵墙。

## 体积与性能

- `utils/recipes.js` 约 571 KB，主包总计 958 KB / 微信限制 2048 KB（47%）
- 菜谱页做了**分页**：一页 30 道，滚到底再追加。
  完整菜谱（含食材做法）不进 `data`，只在 JS 侧的 `this._recipes` 存着，
  列表只渲染精简投影（见 `toListItem`）—— 否则几百道菜的食材做法
  会被 `setData` 整份搬进视图层，列表会卡到飞起。
