# 订阅消息服务端对接说明

## 结论先说

**微信消息下发无法在小程序端完成**，这不是实现取舍，是微信的安全约束。

下发订阅消息要调用：

```
POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send?access_token=xxx
```

而 `access_token` 的获取接口：

```
GET https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=xxx&secret=xxx
```

需要小程序的 **AppSecret**。AppSecret 一旦放进前端代码包，任何人反编译都能拿走，
进而冒充你的小程序调用任意微信接口（发消息、拿用户数据）——微信为此会直接封禁账号。

所以必须有一个跑在你自己的服务器（或云函数）上的程序来发消息。

---

## 本项目已经做完的部分

打开小程序时（`index.js` → `notifier.syncPendingReminders`）会自动完成：

1. 扫描所有纪念日，找出**已进入提醒窗口**的（距今天数 ≤ `remind_days`）
2. 排除 `repeat_yearly = false` 的一次性纪念日
3. 用「类型 + 纪念日 id + 目标日期」生成去重 key，**同一纪念日同一年只记一次**
4. 写入 `reminders` 表（`kind='anniversary'`，`is_read=false`）
5. 弹窗展示未读提醒内容（**这部分不依赖微信，现在就能用**）

也就是说：**你的小程序已经把「该提醒什么」算好并存进数据库了**，
外部服务端只需要定期读取这个表并调微信接口发出去。

---

## 服务端要做的事

### 1. 读取待发记录

表 `reminders`，条件：

```sql
SELECT * FROM reminders
WHERE is_read = false
  AND remind_at <= now()
ORDER BY remind_at ASC;
```

> ⚠️ 该表的 RLS 策略只允许小程序端访问，外部服务端需要用
> **数据库直连账号**或平台提供的管理凭证读取，不能复用小程序的 publishableKey。

### 2. 拼装消息体

字段结构必须与模板完全一致（见 `utils/subscribe.config.js` 的 `TEMPLATE_FIELDS`）：

**纪念日**（模板 ID：`Aoq7MpHbQgO1Uy5hu1hfckQRfu5vuYGp4Lz1S5v0mEQ`）

```json
  "template_id": "Aoq7MpHbQgO1Uy5hu1hfckQRfu5vuYGp4Lz1S5v0mEQ",
  "page": "pages/anniversary/anniversary",
  "data": {
    "thing1": { "value": "小余公主生日" },
    "time2":  { "value": "2027-06-24 00:00:00" },
    "thing4": { "value": "TA的昵称" },
    "thing5": { "value": "情侣" },
    "time7":  { "value": "2026-10-15 16:00:00" }

```

**点餐**（模板 ID：`dkq_mZyzOfRpyvBbUcpCYOQsYIA_fiVCoX4tGazLCu0`）

```json
    "thing2": { "value": "小余" },
    "thing3": { "value": "想去" },
```

### 3. 字段格式硬要求

| 类型 | 要求 | 违反后果 |
|---|---|---|
| `time` | 必须 `YYYY-MM-DD HH:mm:ss`（**带秒**） | 报 `47003` |
| `thing` | 纯文字，**≤20 字符** | 报 `47003` |
| 必填字段 | **不能缺、不能给空串** | 报 `43101` |

`reminders.body` 里已经存好了可直接展示的标题文案；
若要自己重新拼装，请参照 `utils/message.js` 的 `buildAnniversary` / `buildOrder`，
那里已实现截断与空值兜底。

### 4. 发完要标记

发送成功后把 `is_read` 置为 `true`（或新增 `sent_at` 字段），避免重复下发。
一次性订阅的额度很有限，重复发送会快速耗尽用户攒下的额度。

### 5. access_token 要缓存

`access_token` 有效期 2 小时，**不要每次发送都重新获取**（有频率限制）。
缓存到本地，用过期前 5 分钟再刷新。

---

## 错误码速查

| 码 | 含义 | 排查方向 |
|---|---|---|
| `40001` | access_token 无效 | 缓存是否过期，secret 是否正确 |
| `40003` | openid 不合法 | touser 是否传了正确 openid |
| `43101` | 用户拒绝接受消息 | 一次性订阅额度用完了，需用户重新授权 |
| `47003` | 模板字段不合法 | 字段名/类型/长度不符，见上文格式表 |
| `40037` | template_id 不合法 | 模板 ID 抄错，或模板已被删除 |

## 部署选项

| 方案 | 说明 | 适合 |
|---|---|---|
| 腾讯云 SCF 云函数 + 定时触发器 | 与微信生态同账号，配置简单 | 推荐 |
| 自己的服务器 + cron | 完全可控 | 已有服务器 |
| GitHub Actions 等定时任务 | 免费，但访问国内接口不稳定 | 仅测试用 |

无论哪种，**AppSecret 只放在服务端环境变量里**，绝不进代码仓库。
