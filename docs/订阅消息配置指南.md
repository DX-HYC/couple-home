## 一、关键限制（影响方案设计）

微信订阅消息分三种，你的项目只能用第一种：

| 类型 | 授权一次能发几条 | 你的项目能否用 |
|---|---|---|
| **一次性订阅** | **1 条** | ✅ 只能用这个 |
| 长期订阅 | 无限条 | ❌ 仅政务/医疗/交通/金融/教育/公益类目开放，个人小程序申请不下来 |
| 会员订阅 | 会员期内无限 | ❌ 需接入会员体系，开发成本高 |

**「一次性订阅」意味着**：用户点一次「允许」，你只能给他发**一条**消息，发完额度就扣光了。

所以「订阅一次，以后每次纪念日都提醒」是**做不到**的。正确做法是：在**每个值得提醒的节点**（比如新建纪念日时、点菜时）弹出授权，把额度攒起来。这样攒够几次，就能发几次。

> 项目代码已经按这个逻辑写好了：新建纪念日后自动请求一次订阅（`anniversary.js:259`），点菜时请求一次（`recipe.js:138`），写下愿望时请求一次（`wish.js`），额度自然累积。

## 四、字段格式硬性要求（踩坑重灾区）

下发消息时字段格式不对会直接报错 **47003**，消息发不出去。对照检查：

| 类型 | 格式要求 | 示例 | 常见错误 |
|---|---|---|---|
| `thing` | 纯文字，≤20 字符 | `小余公主生日` | 塞进多余空格、超过 20 字 |
| `time` | `YYYY-MM-DD HH:mm:ss` | `2027-06-24 00:00:00` | 只给日期没给时分秒 |
| `character_string` | 纯数字/字母，≤32 | `1024` | 混入中文 |
| `phrase` | ≤5 字符短语 | `还有25天` | 太长 |

## 五、开发环境注意

订阅消息**在开发者工具里模拟不出真实推送**。要验证必须：

1. 编译后用**预览二维码**在真机上打开
2. 真机点「开启订阅通知」，用户点「允许」
3. 用真机触发场景（新建一个纪念日 / 点一次菜）

开发者工具的「订阅消息」面板可以模拟用户授权状态，但**消息是否真的到达微信，需要在真机上验证**。

## 六、还没实现的部分（微信下发必须在服务端）

⚠️ **微信消息下发无法在小程序端完成**——下发接口需要 `access_token`，
而获取 token 需要小程序 **AppSecret**。AppSecret 放进前端代码包会被反编译拿走，
进而被冒充调用微信接口，账号会被封禁。

本项目的云服务只提供 database / auth / storage / llm，**没有服务端函数通道**。

**已完成（现在就能用）**：
- ✅ 打开小程序时自动扫描纪念日、判断是否进入提醒窗口
- ✅ 去重后写入 `reminders` 表，同一纪念日同一年只记一次
- ✅ **弹窗展示提醒内容**（不依赖微信，打开小程序就能看到）
- ✅ 前端订阅授权 + 授权结果入库

**需要外部服务端做**：定期读 `reminders` 表未处理的记录 → 调微信接口下发 → 标记已发。

详细对接说明、消息体示例、错误码速查见 **`docs/订阅消息服务端对接.md`**。

推荐方案：腾讯云 SCF 云函数 + 定时触发器（与微信同账号，配置最简单）。

## 常见问题

**Q：用户点了「允许」，为什么没收到消息？**
A：先确认额度。一次性订阅授权一次只能发一条，且授权后**额度不自动补充**——需要用户多次授权才有更多额度。

**Q：提示「can only be invoked by user TAP gesture」？**
A：`wx.requestSubscribeMessage` 必须在用户点击事件的回调里同步调用，不能放在 `onLoad` 或 `setTimeout` 里。项目代码已经处理好了（都是在点击/创建成功后的回调里调）。

**Q：模板审核不通过？**
A：优先用公共模板库（免审核）。自己申请新模板要人工审核，且**模板类目必须与小程序服务类目匹配**，不对会被拒。

**Q：一次性订阅额度不够用？**
A：在更多节点请求授权来攒额度。项目目前有 3 个请求点（新建纪念日、点菜、写下愿望），可以按需增加。
